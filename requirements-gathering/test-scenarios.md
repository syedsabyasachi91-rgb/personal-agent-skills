# Requirements Gathering — Test Scenarios

## Scenario 1: Vague feature request

**User says:**
> "Ask me some questions to figure out what I need. I want to build a notification system."

**Expected behavior with skill:**
- Asks about purpose: what kinds of notifications, who receives them, why
- Asks about scope and boundaries
- Asks about channels: email, SMS, in-app, push
- Asks about users and stakeholders
- Asks about success criteria
- Asks about constraints
- Synthesizes into a clear spec before proceeding
- Confirms understanding with user

## Scenario 2: Underspecified task

**User says:**
> "Help me clarify what I'm trying to do here. I need a data export feature."

**Expected behavior with skill:**
- Asks about data source and format
- Asks about export format (CSV, JSON, Excel, PDF)
- Asks about scheduling (one-time, recurring)
- Asks about users who will use this
- Asks about constraints (file size, performance)
- Synthesizes before confirming

## Scenario 3: Explicit requirements gathering request

**User says:**
> "I need to gather requirements for a user authentication system. Ask me what you need to know."

**Expected behavior with skill:**
- Explores: auth methods (OAuth, email/password, SSO)
- Explores: user roles and permissions
- Explores: session management requirements
- Explores: security constraints
- Explores: integration points
- Synthesizes and confirms
